# /recall — 召回归档原文

对话里出现 `#STAMP <id> → <路径> — …` 时，摘要**只是导航**，细节可能失真。
需要精确内容时用本命令取回原文。

## 执行步骤

1. **定位文件**：
   - 参数是 12 位十六进制 id → 读 `.stepcode/context-archive/stamp-<id>.md`；
   - 参数是文件名或路径 → 直接读该路径；
   - 参数缺失或找不到对应块 → 先列出当前会话里的全部 #STAMP 行让用户挑选，
     **不要猜**、也不要用相近的块顶替。
2. **读取全文**（用宿主自带的读文件工具）。
3. **基于原文回答**用户的实际问题，而不是把整块原文倾倒出来：
   - 用户问报错堆栈 → 从原文里摘出堆栈；
   - 用户问某个决定 → 从原文里找当时的依据。
4. **冲突处理**：归档原文与当前工作区文件不一致时，说明差异，以**当前文件**为准，
   不要静默采信任一方的旧内容。
5. **失败如实报告**：文件不存在、id 非法、读取失败时，直接说明失败原因与尝试过的路径，
   **禁止**用"原文大概是……"之类编造内容填补。

## 召回纪律（何时必须、何时不必）

**必须召回**：用户引用历史对话原话；需要精确的报错/堆栈/命令输出；需要被删除或
被截断的代码片段；需要确认早前做出的决定及其上下文。

**不必召回**：话题已切换；信息在当前工作区文件里能直接读到（直接读文件更可靠）；
用户明确表示不用翻历史。

## 安全

- 只读操作，不修改归档文件；
- 一次回答只召回所需的最少块，避免把全部归档灌回上下文。
