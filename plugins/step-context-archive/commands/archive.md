# /archive — 上下文归档

把本会话里**已经完成、且不再需要逐字保留**的历史任务块写入归档文件，并在对话中留下
一行索引。这样窗口只承载"索引 + 结论"，被归档的原文需要时再取回，而不是常驻上下文。

## 规则

```json

  "archive_dir": ".stepcode/context-archive/",
  "file_naming": "stamp-<id>.md",
  "id_format": "12 位小写十六进制（块首末消息标识串的 sha256 前 12 位；无法计算时回退 b<块序号>-<yyyymmddhhmm>，不得与已有文件重名）",
  "overwrite": false,
  "outside_default_dir": "须先获得用户同意",
  "content": "任务块原文（不是摘要、不是去重版）",
  "index_line": "#STAMP <id> → <归档文件绝对路径> — 目标：…；关键决策：…；是否完成：…",
  "reporting": "归档结束按块汇报：已完成 / 部分完成（缺什么）/ 未完成，不得只给摘要"
}
```

## 什么时候用

- 会话很长（多轮、多日续接），历史任务块已大量堆积；
- 某些早前任务的细节（大段日志、报错堆栈、被改动的完整代码）**当前不需要**，
  但将来可能要引用；
- 准备继续推进新任务，希望先让窗口"瘦身"。

**不要**用于：仍需逐字保留的当前任务；短会话（还没有值得归档的块）。

## 执行步骤

1. **先划定归档范围**：挑出满足全部条件的块——① 该任务已达成或已明确结束；
   ② 其细节当前不需要；③ 后续可用一句话索引代替。范围拿不准时，先向用户列出
   候选块（标题 + 涉及文件）并确认，不要擅自扩大。

2. **为每个块生成三点摘要**，顺序固定、每点一行：
   - `目标：` 当时要解决什么问题（任务来源）
   - `关键决策：` 实际采用了什么方案、动了哪些文件/命令
   - `是否完成：` 已完成 / 部分完成（缺什么）/ 未完成 + 未决项与下一步

   摘要只做导航，**允许不完整**——细节以归档原文为准。

3. **把块原文写入归档文件**（使用宿主自带的写文件工具，不引入外部脚本）：
   - 目录：`.stepcode/context-archive/`（项目内；用户指定其他位置时从其指定）
   - 文件名：`stamp-<id>.md`，`<id>` 为 12 位小写十六进制
   - `<id>` 生成方式：对"该块首末消息的标识串"计算 sha256 并取前 12 位
     （可用 `node -e` 或平台等价命令）；无法计算哈希时，退化为
     `b<块序号>-<yyyymmddhhmm>` 这类稳定短 id，但**不得与已有文件重名**
   - 写入内容：该块的**原文**（不要写摘要、不要写去重版）
   - **已存在同名文件时不要覆盖**：换一个 id 或先询问用户

4. **在对话中输出索引行**（每块一行，格式固定）：

   ```
   #STAMP <id> → <归档文件绝对路径> — 目标：…；关键决策：…；是否完成：…
   ```

5. **总结完毕后，明确汇报任务是否完成**：按块逐条说明"已完成 / 部分完成（缺什么）/
   未完成"，并指出仍未完成的任务与未决问题。**不要**只给摘要而不汇报完成状态。

6. **如实收尾**：写盘失败、目录不可写、id 冲突等情况，直接说明失败了哪一步、
   尝试过什么，不要谎报成功，也不要把没写进文件的内容说成已归档。

## 安全红线

1. **只归档、不销毁**：不得删除或改写会话原始消息与已有归档文件。
2. **不越界写盘**：默认只写 `.stepcode/context-archive/`；要写到别处必须先获得用户同意。
3. **不夹带机密**：归档内容若含密钥、token、凭据字面量，先提示用户，由用户决定是否归档。
4. **不编造原文**：归档文件必须是块原文本身，不得用摘要冒充原文。
5. **不改用户配置**：本命令不修改 `settings.json`、不安装任何依赖。
